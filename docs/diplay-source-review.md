# DiPlay Legacy source review for wireless CarPlay

Read-only review of upstream commit [`fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1`](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/commit/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1), recorded 2026-10-31. This is source analysis, not a build, runtime profile or proof that the owner’s installed APK matches this commit. No DiPlay APK was built or modified for this review.

## Code path and existing measurements

- [`ScreenStream.kt`](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/shared/src/main/java/com/shilapi/xcertplay/airplay/ScreenStream.kt#L127-L242) receives TCP video packets, places encrypted frames in a 10-frame queue with a 30 ms offer timeout, then decrypts and delivers them. Its `StreamReceiveStats` covers read/processing time, interarrival gaps and average/maximum decrypt time. Optional native ChaCha has self-test/counters with a fallback; older benchmark claims should not be assumed for this API 27 unit.
- [`VideoDecodeQueue.kt`](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/shared/src/main/java/com/shilapi/xcertplay/media/VideoDecodeQueue.kt) limits its queue to 60 frames and 8 MiB. Decoder-side maximum frame age is 800 ms; a 250 ms comment is stale. Overflow/resync protects H.264 reference continuity. Arbitrarily dropping old encoded frames is not a safe first optimization.
- [`AndroidMediaSink.kt` configuration](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/shared/src/main/java/com/shilapi/xcertplay/media/AndroidMediaSink.kt#L1243-L1468) tries tuned hardware, minimal hardware and then software fallback. Tuned configuration requests priority 0 and up to 8 MiB input; its low-latency flag requires API 30+, so it does not apply to this API 27 unit. A software-first workaround keys on `OMX.atc.video.decoder` for AC83xx, not the unit’s advertised `OMX.MTK.VIDEO.DECODER.AVC`. Actual runtime decoder choice remains unknown.
- [`AndroidMediaSink.kt` output path](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/shared/src/main/java/com/shilapi/xcertplay/media/AndroidMediaSink.kt#L1713-L1755) releases decoded output to a Surface with optional pacing. [`VideoStats.kt`](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/shared/src/main/java/com/shilapi/xcertplay/media/VideoStats.kt) emits 5-second `rx`/`shown` FPS, maxGap, bitrate, recoveries, touch-to-frame, decode p50/p90 and pacing delay. Here `rx` means post-decryption submission, and `shown` means output released for display; neither is a direct network-ingress or physical-panel timestamp.
- [`DiPlayActivity.kt` diagnostic report](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/common/src/main/java/com/shilapi/xcertplay/DiPlayActivity.kt#L4764-L4835) exports version, preferences, saved settings, negotiation and session logs. Saved settings need not equal active runtime settings, and a logging gate can suppress logs. Native first-frame crypto details may appear only in `Log.i`, not the report.

## Consequence for the next task

Inspect one report from the **installed** DiPlay build before implementing any collector. Record the installed version, active codec/Surface and negotiated settings where available. If stage timing is missing, scope a bounded profiling patch to crypto implementation and counters, decrypt/decode-queue residence p50/p90, high-water marks and drop reasons, and optional API 27 `OnFrameRenderedListener` callbacks explicitly labeled as callbacks rather than panel presentation. Use test markers and bounded, redacted logs. Exclude media payloads, keys, SSIDs and IP addresses from exports.

The [upstream build notes](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/fd907cd50bbcc38aac448b25cdfbc0ac9d69d2d1/docs/BUILD.md) state that an ordinary source APK lacks accessory identity and needs external runtime authentication assets to work standalone. The lawful availability of those assets, release parity and connection behavior are unresolved. Do not present a custom APK as equivalent to the installed working release, or extract/publish identities. Use the [project’s coordinated test plan](wireless-carplay-performance.md) for the single later parked-car session.
